# Security Policy

## Supported versions

Before Kessel's first release, security fixes are applied to the `main` branch.
After release, security fixes are applied to the latest published version and
the `main` branch. Earlier versions are not supported.

## Reporting a vulnerability

Do not disclose a suspected vulnerability in a public issue, discussion, or
pull request. Submit the report through
[GitHub private vulnerability reporting](https://github.com/waderylan/kessel/security/advisories/new).

Include the following information when available:

- The affected Kessel version or commit.
- The affected command, endpoint, or provider integration.
- Steps sufficient to reproduce the issue.
- The expected security impact.
- Any proposed mitigation or remediation.

Remove provider credentials, access tokens, Kessel API keys, account identity,
prompts, responses, and other sensitive information from all submitted
materials.

Rylan Wade will assess the report and coordinate remediation and disclosure as
appropriate. Submission of a report does not authorize access to another
person's systems or data, service disruption, or any activity that violates
applicable law or provider terms.
